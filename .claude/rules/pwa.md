# PWA — offline, updates and user data

The app is installed on iPhone home screens and used offline. Users' progress lives only on their device.
Losing it or getting stuck on an old version is the worst possible bug — every change is checked against this file.

## Service worker (vite-plugin-pwa)

- Use `vite-plugin-pwa` with `strategies: 'generateSW'` unless custom SW logic is really needed (`injectManifest`).
- `registerType: 'autoUpdate'` + `workbox.clientsClaim: true` + `skipWaiting: true`: a new version activates by itself,
  the page reloads once on `controllerchange`. Never reload in the middle of user input; never reload on the very first install.
- Register via `virtual:pwa-register` (`registerSW({ immediate: true, onRegisteredSW })`) and call `registration.update()`
  on `visibilitychange → visible` — iOS standalone apps are rarely restarted.
- Precache the app shell (`globPatterns: ['**/*.{js,css,html,svg,png,webmanifest}']`). Hashed assets need no runtime cache.
- `navigateFallback: 'index.html'` (with hash routing this is the only page anyway).
- Keep the SW **at the same URL and scope** as the previous version (`<base>/sw.js`). Changing the SW filename or scope
  leaves old installs controlled by the old worker forever.
- When replacing a hand-written SW: the first Workbox version must delete legacy caches
  (`caches.keys()` → delete `bachata-pwa-*`) in `activate`. `cleanupOutdatedCaches: true` only cleans Workbox caches.
- No caching of cross-origin requests unless explicitly needed; no `opaque` responses in the cache.
- `devOptions.enabled` only while debugging the SW; check real behavior with `npm run build && npm run preview`.

## Manifest and iOS

- Manifest is generated by the plugin config: `name`, `short_name`, `start_url: '.'`, `scope: '.'`, `display: 'standalone'`,
  `theme_color`/`background_color` equal to the CSS tokens. Icons: only `icons/icon.svg` (owner's decision, no PNG) —
  manifest `sizes: 'any'`, `type: 'image/svg+xml'`.
- Keep iOS meta tags in `index.html`: `apple-mobile-web-app-capable`, `apple-mobile-web-app-status-bar-style`,
  `apple-touch-icon` → `icons/icon.svg`, `viewport-fit=cover`.
- Standalone detection: `matchMedia('(display-mode: standalone)') || navigator.standalone`.
- iOS has no `beforeinstallprompt` — the install hint is a manual instruction, shown once per session, dismissible.
- `base` in `vite.config.ts` equals the GitHub Pages path (`/bachata-roadmap/`); all asset URLs come from
  `import.meta.env.BASE_URL`, never absolute `/…`.

## User data (localStorage)

- All persistence goes through `lib/storage.ts`. Components and stores never call `localStorage` directly.
- Storage keys and the stored shape are a **public contract**. Changing them requires:
  1. a new version number in the key or a `version` field,
  2. a pure migration function `migrateVx→Vy` with a unit test on real old payloads,
  3. reading the old key on startup and keeping it until the new one is written successfully.
- Every read is validated (`unknown` → type guard). Invalid data → restore from the last-good backup → otherwise defaults,
  and keep the corrupt payload in a separate key for recovery. Tell the user in a toast what happened.
- Every write is in `try/catch`: `QuotaExceededError` and private mode must not crash the app; fall back to in-memory state
  and show a message.
- Progress item ids must be stable across releases. Never derive them from array positions in new code;
  if legacy positional ids exist, keep a mapping and test it.
- Call `navigator.storage?.persist?.()` once after the first meaningful save (reduces eviction risk).
- Persist on change (debounced if writes are frequent) and on `visibilitychange → hidden`; iOS may kill the app without `unload`.

## Offline UX

- The app must fully work offline after the first visit: no network requests in the critical path, no CDN fonts or scripts —
  everything is bundled.
- No `alert`/`confirm` for important flows on iOS standalone; use in-app dialogs.
- Respect safe areas (`env(safe-area-inset-*)`) and `100dvh`; touch targets ≥ 44px.

## Release checklist (see the `pwa-release-check` skill)

- Fresh install works offline; update from the previous production version keeps entities and progress;
  the old SW is replaced; Lighthouse PWA/installability has no errors.
